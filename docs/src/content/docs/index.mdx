Home Assistant Bridge keeps one [Home Assistant](https://www.home-assistant.io) WebSocket connection open per machine and serves it to local apps over a single Unix socket. Status bars, keyboard shortcuts, scripts and your own apps all share that one connection, instead of each opening their own.

```bash
# Toggle light.desk
ha-bridge light toggle desk

# Print sensor.office_temperature now and on every change, as JSON lines
# that status bars, widgets and scripts can read
ha-bridge watch sensor.office_temperature --bar-json
```

## How it fits together

- `ha-bridge serve` runs as a systemd user service. It connects to Home Assistant, caches every entity's state and keeps it current.
- Every other command is a small client. It connects to the bridge socket, makes one request and exits, or streams updates for watchers.
- Your own scripts and apps can use the bridge too:
  - Run the same commands. Watchers print [JSON lines](/using/bar-json) to parse.
  - From TypeScript, use [`@timmo001/effect-ha-bridge`](/libraries) to talk to the socket directly.
  - From any other language, speak the [bridge protocol](/using/protocol).
